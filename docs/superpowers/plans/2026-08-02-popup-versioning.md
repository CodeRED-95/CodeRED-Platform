# Popup Versioning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rediseñar el popup de la extensión Buscador Shalom y centralizar la versión `2.0.0` en plataforma, extensión, API y documentación.

**Architecture:** La versión canónica vive en configuración PHP y en un módulo TypeScript compartido de la extensión. El popup consume esa versión y estado local mediante runtime/storage existentes; no reintroduce búsqueda ni catálogo visual. La plataforma expone `/api/v1/version`, comando artisan y footer/header con la misma versión.

**Tech Stack:** Laravel, Blade, Artisan, Vite, Manifest V3, TypeScript, Vitest, PHPUnit/Pest-style Feature tests.

## Global Constraints

- Versión canónica actual: `2.0.0`.
- Popup: tema oscuro, ancho mínimo 520px y máximo 720px, layout 2 columnas, stack vertical bajo 560px.
- Popup mantiene solo estado del token, Solicitar token y Configurar token/Administrar token.
- No modificar búsqueda inyectada en Shalom, selección Chosen ni catálogo salvo lectura de estado/versionado.
- No editar `dist` manualmente; solo regenerar con build.
- Documentar README, CHANGELOG y roadmap/versionado.
